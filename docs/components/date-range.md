# DateRangePicker：连续日期区间

当需求是“浏览日期、选择连续起止日，再确认一个区间”时，先比较本组件。日期代表订单、考勤、预约或其他业务由宿主决定；演示名称不是范围限制。单个时间点、多个不连续日期、只能选有数据日期，都需要比较或扩展不同规则。

网站入口：`/components?category=interaction#date-range`。真实调用示例：[date-range-example.tsx](../../src/examples/date-range-example.tsx)。完整迁移步骤见 [通用复用方法](../UI-REUSE.md)。

## 输入与输出

| 参数 | 类型和含义 | 调用方约束 |
| --- | --- | --- |
| `today` | `string`，业务时区下的今天 | 有效 `YYYY-MM-DD`；由宿主决定时区并更新 |
| `value` | `DateRange`，已确认区间 | `{ start: string; end: string }`，日期有效且起日不晚于止日 |
| `onChange` | 接收一个 `DateRange` | 宿主更新确认值，再按需查询或保存 |
| `dataDates` | `ReadonlySet<string>`，有数据日期集合 | 与区间同用 `YYYY-MM-DD` 日键；只表达已知标记 |

区间两端均包含。模型用固定格式日键排序，按 UTC 做日历算术，不自行读取浏览器时区决定业务今天。调用方需要把真实时间戳按自己的业务时区转换成日键；当前示例选择的时区不是组件的唯一可用时区。

`dataDates` 只影响选中区间的着色，不限制日期选择。空集合表示“没有被标记的日期”，不能让用户把尚未加载的数据误解为已确认无数据；加载和未知状态由宿主先处理。

## 显示月份、草稿与已确认值

组件内部保留展开状态、显示月份、草稿和第一次点击的日期；宿主持有 `value`。当前初始面板展开，显示月份来自初始 `value.start`。

| 操作 | 当前行为 | 是否调用 `onChange` |
| --- | --- | --- |
| 上年、上月、月份输入、下月、下年 | 只切换双月视图 | 否 |
| 第一次点日期 | 草稿暂为该日到该日，等待结束日期 | 否 |
| 第二次点日期 | 草稿形成区间，逆序自动排序 | 否 |
| 应用日期 | 提交草稿、关闭面板；只点一天也可以应用 | 是 |
| 日期快捷按钮 | 生成快捷区间、立即提交并关闭 | 是 |
| 再次打开触发按钮 | 从当前确认值恢复草稿，清除未完成的起点 | 否 |

外部 `value.start` 或 `value.end` 改变时，组件同步草稿及显示月份、清除未完成的起点和快捷项状态；不改变展开状态，也不触发 `onChange`。仅传入相同日期的新对象不会打断草稿。宿主切换查询上下文时应同步提供该上下文的确认值；若新旧上下文日期相同但也要求丢弃草稿，需在宿主明确重建或重置策略。

## 快捷区间与设计理由

| 快捷项 | 日期口径 |
| --- | --- |
| 今天、昨天 | 对应单日 |
| 本周 | 周一到周日 |
| 近七天、近三十天 | 包含今天的最近七/三十个自然日 |
| 本月、上月 | 完整自然月 |
| 本季度 | 完整自然季度 |

本周、本月和本季度可能包含今天之后的日期，不能当作“截至今日”的统计口径。快捷项及其规则目前固定在模型中，不是可传入参数。

浏览与确认分离，让用户翻月和调整区间而不触发中间查询；快捷项因为语义已完整，直接确认。描边表示边界、填色表示区间内有数据，二者分开后可识别“选中了但无数据”的日期。紫色是视觉约定，不是数据可用性的唯一表达；日期按钮还带有日期与数据标记的无障碍名称。

## 迁移到未列举业务

1. 确认保存的是含两端的连续日期区间，明确自然日、时区和快捷项口径。完成条件：没有把时间戳或截至今日规则当作当前默认规则。
2. 把宿主数据映射为区间和日键集合；区分无数据与尚未加载。完成条件：值有效、起止有序、数据标记有来源。
3. 将 `onChange` 接到宿主确认值，查询只使用该确认值；月份导航和日期草稿不触发业务请求。完成条件：确认时机符合目标流程。
4. 处理上下文切换及外部重置，再核对响应式和键盘行为。完成条件：旧草稿不会误用于新的对象或业务范围。

| 业务映射示例 | 保持的结构 | 宿主替换内容 |
| --- | --- | --- |
| 订单报表期间 | 连续起止日、含两端、确认后查询 | 业务时区、订单日汇总标记、报表请求 |
| 设备巡检记录期间 | 连续起止日、含两端、确认后查询 | 设备上下文、巡检日标记、上下文切换策略 |

对象和接口不同不妨碍复用同一交互。若后者要求只能选有记录日，就已经改变可选规则，需要先补禁选契约。

## 必须保留、可以调整、宿主负责

| 层次 | 约定 |
| --- | --- |
| 必须保留 | 日期键口径、范围排序、浏览不提交、草稿与确认分离、确认回调、边界和数据标记的区别 |
| 可以调整 | 输入日期、数据标记、容器与有作用域的颜色/间距；快捷项、按钮文案和初始展开不是现有 props，变更需同步契约 |
| 宿主负责 | 业务时区、数据获取、加载/未知/错误、真实查询、持久化、权限和上下文重置 |

月份导航使用浅蓝组，快捷选择使用紫色，以区分“浏览”与“确认”。允许按目标主题调整，但仍应把两种作用分组。窄屏双月改为上下排列，注意外层宽度、日期点击区域、长文案和底部按钮折行。

## 键盘及尚未支持的能力

按钮可用 Tab 聚焦、Enter 或空格激活，月份输入遵循浏览器原生操作。当前没有日历网格的方向键移动、Home/End、PageUp/PageDown 漫游，也没有 Escape 或点外部自动关闭协议。可通过触发按钮收起，或确认后关闭；不要把现有 Tab 支持描述成完整日历键盘方案。

当前不支持空区间、时间选择、多段区间、禁选日期、最大跨度、工作日历、自定义快捷项、加载指示和内置输入日期校验。目标需要这些能力时，先定义约束与错误路径再扩展；`dataDates` 不能兼任禁选规则。

## 迁移验收

- 翻月、跨年和月份输入只改变视图；应用前宿主确认值不变。
- 正序、逆序、单日、闰月区间计算符合契约。
- 快捷项一次确认并关闭；自然月/季度与“截至今日”的差异已被业务接受。
- 空数据集合、局部标记及未加载状态含义明确，无数据日仍能被选中。
- 外部重置及切换业务对象不误提交旧草稿；Tab 可到达必要操作，窄屏不遮挡。
- 用未在文档列举的业务说明时间口径、输入映射和确认行为。
