## 1. 已确定的规则

| 项目 | 当前决定 |
| --- | --- |
| HRM | 仅负责账号和系统准入。按 HRM 角色筛选候选成员；后续角色变化不撤销招商任职和授权。账号禁用或准入撤销阻止访问，包括 admin。 |
| 组织 | 本系统独立维护；支持多个平级负责人和多组织、多层任职。称谓不自动授权。 |
| 角色 | 一个可复用角色统一配置页面、按钮、默认查看范围、默认操作范围。 |
| 组织分配 | 选择具体节点，指定仅当前节点或节点及全部下级。新增成员自动获得适用组织授权。 |
| 任职分配 | 点击具体人员卡片，只作用于该任职，不按姓名或人员身份扩散到其他任职。 |
| 层级 | 系统按树深度显示 L1、L2 等，不限制总层数。同级仅是批量勾选工具，保存实际节点 ID；新增同级不自动纳入。 |
| 下级规则 | 明确选择含全部下级，才包含未来新下级。无个人排除项。 |
| 数据范围 | 默认以接收人的任职组织为锚点；可在本次分配中指定查看、操作组织，操作不得超过查看。范围覆盖不改变人员或业绩归属。 |
| 多来源 | 按允许并集。动作必须和同一授权来源的数据范围一起判断，不能跨来源拼接扩权。页面可由另一角色提供。 |
| 全页 | 持续包含当前及未来动作，支持隐藏、仅可见的按钮例外；例外只限制当前角色，不否决其他角色。 |
| admin | 初始超级管理员，自动包含未来页面、按钮和数据；业务状态和流程规则仍生效。 |
| 本人数据 | 以业务归属人为准，不以代录人、创建人、实际操作者作为本人边界。 |
| 组织移动 | 直接授权随稳定节点保留，旧上级继承失效、新上级继承生效；保存前展示变更影响。 |
| 调组 | 结束旧任职、创建新任职，旧任职授权失效。业务交接另行处理，已确认历史业绩不随调组重算。 |
| 生效 | 模型保存后立即重算，不需重新登录；生产要求下一请求使用新权限，本演示没有真实服务端。 |
| 初始化 | 不转换旧权限；示例角色仅是模板，22 名虚构人员、23 条任职初始均未分配角色。admin 不计入组织人数。 |

## 2. 操作流程

### 拓扑勾选与实时反馈（2026-09-07 补充）

分配角色时，每个组织框提供“仅当前节点”和“当前节点及全部下级”两个互斥勾选。不同节点可以混合选择，切换其中一个节点不会改变其他节点。人员卡也提供直接勾选。荧光、去重人数全部从未保存草稿即时计算，不等待“保存授权”；取消勾选即时移除高亮，其他来源仍覆盖时保留并提示。保存只提交，随后关闭荧光。

左侧“勾选授权人员 / 勾选查看范围 / 勾选操作范围”分别编辑接收人、查看组织、操作组织。右侧改变数据范围也会自动切换对应荧光视图。自定义组织即使暂未选接收人也会立即高亮。每节点是否包含下级存为 `subtreeNodes`，旧缓存缺少此字段时沿用原 `descendants`，编辑后保存明确的逐节点意图。

浏览器已在未点击保存时验证：仅部门节点亮 2 张任职卡；改为部门及下级立即亮 23 张；取消勾选立即回到 0。未提交配置不改变已有授权。


界面沿用原 A 拓扑：部门负责人在紫色部门框内，组负责人在独立组节点框内；组员名录位于下方蓝色独立框，通过连线连接。工号、职级、绩效底色使用原示例快照，缺失显示待统计。角色与授权面板按需打开，默认展示完整画布。

负责人/组员卡片位置仅用于展示，不是授权筛选，也不自动授予角色。新增任职明确选择卡片位置；已有 v2 缓存按原样本的任职关系恢复位置，不根据角色名称推定。

1. 打开“角色库”。可新建空角色、编辑角色名，配置默认查看和操作范围、页面访问及按钮三态。
2. 勾选“全页授权”表示持续规则；按钮下拉可建立例外。点击恢复默认，移除该按钮例外。取消全页时保留当前已登记按钮的实际状态，未来新增动作不再自动授权。
3. 点击“分配角色”，选择角色；左侧点击组织框批量选择，或点击人员卡选择具体任职。组织选择和指定任职可并存，计算时去重。
4. 在各组织框勾选“仅当前节点 / 当前节点及全部下级”。“勾选同级”先选查找范围及数字层级，保存当前实际节点，不保存动态层级规则。搜索只改变显示，不缩小已选范围。
5. “勾选授权人员”荧光标出接收任职；“合并已有授权预览”合并现有同角色授权显示覆盖人员。查看人员详情可进一步检查所有角色的完整有效权限及来源。
6. 切换“勾选查看范围 / 勾选操作范围”，荧光标出数据组织；本人范围高亮对应人员卡。此时点击组织框指定该数据范围，不修改接收人员。右侧也可明确设置自定义范围、是否含下级。
7. 保存校验操作范围不超过查看范围，保存或取消后高亮立即消失。日常不持续高亮。
8. 人员卡可查看当前任职授权或全部任职合并结果，分辨来自具体人员授权还是组织继承；支持调组、结束任职。
9. 组织节点可继续新增下级、重命名或移动；不能移动根节点、成环或移到自身下级。有任职、事实或授权引用的节点不能直接删除。
10. “权限试用”选择人员后，在右侧的示例业务区验证页面、按钮三态、记录过滤和编辑边界。关闭模拟准入即时拒绝；切换模拟 HRM 角色不撤销任职。可模拟未来新增按钮。

## 3. 可手算的场景

### B01 节点、子树与未来同级

Given 部门下有 A、B，选“部门及全部下级”；When 新增 C 并添加任职；Then C 的人员自动获得该角色。

Given 使用 L2 快捷勾选 A、B，选择仅当前节点；When 新增同级 C；Then C 不获得角色。逐项选择全部当前子节点也不升级为父级授权。

### B02 任职锚点与并集

Given 给部门全部下级发“组织管理”，该角色范围为任职组织及下级；Then A 的人员只能在 A 范围使用该角色，B 的人员同理。部门任职人员的范围是部门树。

Given 同一人有部门和 A 两条任职，只点击 A 的卡片授权；Then 部门卡不因此获得该授权，个人全部任职结果可合并 A 来源。任职结束后，再加入同一节点产生新 ID，不恢复旧直接授权。

### B03 不拼接跨角色操作范围

Given 甲在 A 有编辑角色，另外获得 B 只读角色；When 查看 B；Then 可以读取 B，但不能把 A 的编辑动作与 B 的查看范围拼成编辑 B。

Given 角色甲提供页面访问、角色乙提供编辑动作与 A 操作范围；Then 可以进入页面并编辑 A；单持乙而没有页面访问时拒绝。

### B04 全页、按钮例外与三态

Given 全页角色把删除设为隐藏；Then 该角色不允许删除，未来新增动作仍默认可用。

Given 另一角色允许删除且其操作范围覆盖目标；Then 删除允许。仅可见优先于隐藏、可用优先于仅可见；不存在全局 deny。

### B05 归属与生命周期

Given 人员跨组只读授权；Then 人员任职与事实归属不变。调组不自动转移现有事实。

Given 节点移动到新上级；Then 直接授权保留、继承重新计算，L 数字自动变化。权限变更弹窗提示影响任职数量及相对范围变化。

### B06 准入与撤销

Given 人员有有效角色；When HRM 候选角色变化；Then 授权保留。When 账号或准入关闭；Then 页面和动作均拒绝。admin 也受准入限制。

Given 有两个授权来源；When 撤销一条；Then 其他来源仍生效。保存角色编辑后，权限试用即时重算。

### B07 范围验证与预览

Given 当前组织暂时没有事实；When 配置超出查看范围的操作范围；Then 仍拒绝，不能用当前空数据集证明配置安全。

Given 授权草稿存在；Then 只预览，不修改已保存状态；保存、取消后荧光消失。组织覆盖中的某人不能被单独排除。

## 4. 实现入口和存储

- `src/pages/figma-organization-page.tsx`：当前 A 页面入口。
- `src/components/permissions/topology-workspace.tsx`：递归组织画布、角色库、授权编辑、人员来源、组织与任职编辑、试用业务区。
- `src/components/permissions/topology-model.ts`：稳定节点/任职模型、后代集合、授权来源、动作与范围配对、范围包含验证、缓存校验。
- `src/topology-authorization.css`：A 专用布局、荧光样式和响应式规则。
- `tests/topology-authorization.test.ts`：新模型的行为回归测试。
- `src/template-app.tsx`：A 使用独立 v2 演示，不再被旧 v1 的人员功能角色守卫拦截；其他模板继续使用旧演示。

`sessionStorage` 键 `uimodel:topology-authorization:v2` 保存已提交角色、组织、人员、任职、授权及虚构事实。普通分配草稿刷新丢弃；现场角色编辑另以 `uimodel:topology-onsite-draft:v2` 保留跨页面草稿，返回 A 后统一保存或取消，不应当作已生效授权。恢复默认演示只操作这个新键，不改旧模板状态。损坏或不兼容缓存恢复演示并提示，此处恢复 admin 不可作为生产失败策略。

范围以模式和节点根 ID 保存；数据和任职保留各自稳定 ID。新增空组织不产生人员或业绩。当前 22/23 来自真实展示样本的去重计算，不使用原稿 36 人汇总作为授权名单。

## 6. 2026-09-07 交互修正

- 角色库 → 编辑角色 → 在页面中点选授权：组织页面标题配置页面访问/全页规则；人员卡、添加任职、新增下级、编辑组织、授权入口点击后选中相应动作，在右侧设置隐藏/不可用/可用。捕获点击，避免执行实际新增等操作；与角色树编辑同一份草稿，保存统一提交，取消全部丢弃。新增下级、添加任职和编辑组织分别配置。线索/报表使用本地示例业务页面点选，不代表已接入招商真实页面。
- 快捷选择同级改为替换组织勾选，启用后修改根组织或层级立即更新荧光；空结果清空组织部分。单独指定任职仍保留，界面明确说明。清空选择同时退出快捷模式。节点依旧保存具体 ID。

## 7. 跨页面点选、权限树和卡片拖动画布

- 页面权限改为紧凑树：页面为父节点，按钮为子节点，默认折叠；支持搜索、全部展开/折叠。页面旁“打开并点选”导航到实际模板；线索和报表仍明确标注“打开示例并点选”。
- 页面目录加入 UIModel 已有模板路由。每页仅列已登记的按钮，尚无登记动作的页明确说明仅能配置页面访问，不宣称所有业务控件已接入。
- 进入点选后，角色草稿使用独立 `uimodel:topology-onsite-draft:v2` 在同一标签页跨页面保存；不改已保存角色。其他模板的 `TopologyOnsiteBridge` 接收草稿并复用已登记按钮的点选接口；返回 A 页恢复编辑，统一校验、保存/取消。退出点选清除跨页面模式；普通授权草稿仍不持久化。
- `topology-onsite.tsx` 是跨页桥接入口。其他模板未开启 v2 草稿时沿用原来的 v1 演示；当前仅接通 v2 配置，不宣称其他模板运行时已切换到 v2 角色鉴权。
- “拖动画布”默认开启。卡片和空白处按住移动超过 5px 才判为拖动，拖动不触发人员选择/点选授权；轻点仍执行原点击。输入框、范围复选框、维护按钮不启动拖动。关闭拖动模式后停止画布拖动，复位清除位移。

浏览器验证：权限树打开真实门户，开启页面访问后返回 A 页，相同角色草稿中的门户权限仍为勾选；取消草稿。人员卡拖动右 80px、下 60px，整图位移对应变化且人员面板未打开；随后轻点同一卡片正常打开人员面板。门户内部入口受原登录状态影响，未以真实账号验证入口动作，不能据页面导航验证推定全部按钮已接入。


## 8. 快速使用说明书

A 页工具栏点击“A 拓扑说明书”打开本文，目录可跳转章节，关闭或按 Escape 返回原画布。阅读不保存、不取消角色或分配草稿，也不改变任职与授权；网页全屏下仍可打开。

首次使用按“角色库 → 编辑角色 → 保存角色 → 分配角色 → 勾选组织或任职 → 查看/操作范围 → 保存授权 → 权限试用”操作。角色库中的模板不是已经授予人员的权限；卡片显示“尚未授权”属于初始状态。

### 8.1 三种勾选分别代表什么

- 授权人员：选择谁接收角色，以组织规则或具体任职 ID 保存。一个人有多条任职时，单点卡片只选这一条。
- 查看范围：接收人能读取哪些组织的业务数据；自定义覆盖不改变人员所属组织。
- 操作范围：接收人能对哪些组织的数据执行已获准动作；必须落在查看范围内。仅有范围没有动作授权也不能操作。
- “本组织人员”同时包括负责人和下方直属组员；组员名录不是子组织。“含下级”才持续覆盖未来子组织；同级快捷选择只保存此刻的实际节点。
- 荧光和去重人数是当前草稿预览，保存或取消后消失，不能把高亮误认为已保存授权。

### 8.2 数据汇总与权限案例

假设部门 D 下有 A、B，A 的事实 F1=100、F2=200，B 的事实 F3=300，部门直属事实 F4=40。按事实归属汇总，A=300、B=300、D=640。D 有两名平级负责人，或同一负责人又在 A 任职，都不能把 D 算成 1280；人按 personId、事实按 factId 去重。

某人在 A 有编辑来源，在 B 只有读取来源：可见合计可以是 600，但 B 的 300 不可编辑。每条事实必须有同一来源同时满足动作、查看范围和需要的操作范围；不能拿 A 的编辑动作搭配 B 的读取范围。跨组织查看不把 B 的业绩记到 A。已结算历史事实不随人员调组重算。

本人数据指事实的业务归属人，不是代录人。例：张三替李四录入订单，若 owner 为李四，“本人”范围应归李四。组织人数与任职数不同，当前样本为 22 人/23 条任职，不沿用旧图 36 人统计作为授权名单。

上述金额与汇总是设计案例，不是当前 KPI 的实际计算。现有试用区提供虚构记录的过滤与编辑判定；完整业务金额汇总、历史结算和真实写入尚未实现。

## 9. 实现方式与后续 Agent 接入

### 9.1 计算链路

TopologyWorkspace 读取 v2 状态并递归绘制组织树；recipients 将组织/子树/任职选择解析为有效任职集合；sources 返回人员各任职对应的角色分配来源。scopeNodes 以接收任职为锚点展开相对范围，grantErrors/validRanges 在保存时校验操作范围包含关系，不依赖当前是否有业务记录。

pageAllowed 先检查人员启用与系统准入，再检查页面授权；effectiveButton 合并来源的三态，决定展示。allowedFact 对具体记录逐来源判断动作和范围，不能只用按钮可见性代替记录权限。admin 在通过准入后绕过功能和数据范围限制，但业务状态仍在操作入口检查。

角色的 pages 保存 access、full 和 buttons 例外；full 是持续授权规则，未来动作继承，buttons 可覆盖本角色默认。Assignment 保存角色、接收节点/任职、逐节点下级意图及可选 read/write 覆盖。修改角色会影响引用它的分配，覆盖范围优先于角色默认。

### 9.2 树与现场编辑

角色树和 A 现场点选编辑同一 roleDraft。现场通过 data-permission-page/action 与捕获点击定位权限，不执行业务变更。跨其他模板页面由 topology-onsite.tsx 的 TopologyOnsiteBridge 携带角色草稿；未登记内部按钮不自动成为权限资源。线索/报表点选只是演示页面，不能声称接入真实系统。

组织选择的 nodes 是稳定 ID，subtreeNodes 逐节点表示含下级；缺失时才兼容 descendants。任职结束使直接任职授权失效，新任职使用新 ID。节点移动保留节点直接授权，重新计算旧/新上级继承；不隐式转移事实归属。

### 9.3 说明书与生产边界

说明书入口在 topology-workspace.tsx，复用 Dialog 和 organization-bdd-guide.tsx；正文唯一来源是本 Markdown，通过 ?raw 导入。旧版本保存在 docs/history，不混入当前规则。更新正文需运行构建，不能只修改历史说明书。

正式接入必须由服务端提供可信身份、准入、人员和稳定任职；保存授权需管理权、并发版本和审计。每次业务 API 独立检查动作与数据范围，撤销须使后续请求失效。浏览器 sessionStorage、演示 admin、UI 按钮和荧光都不是安全边界。各系统授权独立，HRM 角色仅用于候选筛选，不自动撤销本系统既有任职。
