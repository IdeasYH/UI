`FigmaOrganizationGraph` 接收 `department`、搜索后的 `groups`、`query`、`onClearSearch` 和 `onAction`。图形内部仅维护视图状态，不写业务数据。

`FigmaOrganizationDialog` 接收 `department`、`action`、`onClose`、`onConfirm`。确认回调返回错误字符串时保留表单并显示错误；成功由父页面更新数据并关闭弹窗。取消、Escape 和遮罩关闭均不提交。

`applyFigmaAction(department, action)` 返回 `{ department, error }`，不修改输入对象。出错时返回原对象。动作包括新增/重命名/删除空组、重命名部门、新增/编辑成员、调岗、离职。UI 表单不直接改数组。部门及业务组都有“编辑节点”“删除节点”文字按钮；当前编辑指修改名称，不含变更父级或任命负责人。删除须二次确认，有负责人、汇总人数或名录记录的组不可删除，唯一根部门始终保留。删除空组同步清理本页权限配置对该组的显式引用，不删除人员及业务数据。

## 组织与权限模型

### 2026-09-05：人员范围与识别标签交互

当前交互由 `person-access.tsx` 承载。每个负责人和组员都有权限、标签按钮。权限按人员 ID + 节点 + 任职类型保存，默认负责人看本人及下级，组员看本人；可以改为看本人或看本系统全部。下述早期“共享完整范围”表述指默认配置，显式范围配置优先。

额外组织使用当前部门及各业务组构成的两级树。支持展开、搜索保留父路径、整部门勾选、部分选择半选、右侧移除/清空。搜索不限制上级勾选范围；主动勾选整部门才包含未来新增业务组。取消其一个子组后变为显式子组名单，不再包含未来新增子组；逐个勾完当前全部子组也仍是显式名单，不自动升级为动态父级授权。当前示例没有其他事业部数据，不虚构组织分支。

特殊角色仅为识别标签：顶部添加名称和唯一稳定编码，名称可修改，编码不可改；每人可选多个标签，跨层同 ID 共享。HRM 继续负责功能和按钮权限，标签不授予权限，额外范围不影响组织归属、人数或绩效汇总。

全部设置仅在页面内存中保存；取消不提交，刷新或恢复示例清空。本次未接 HRM、真实业务 API、授权执行或权限过滤；“本系统全部”是展示语义，接入时需服务端提供明确系统 ID、有效任职 ID 和范围校验。

工具栏“组织与权限说明书”按钮展开 `figma-architecture-guide` 区域，默认不显示独立说明条。展开后提供原理概览和完整 BDD 说明书，正文直接来自 [组织权限 BDD](ORGANIZATION-PERMISSIONS-BDD.md)，避免网页与文档内容漂移。BDD 包含具体输入、动作与预期、计算案例、生产实现检查表以及待确认决策，不代表 UI 已接通后端授权。模型按以下顺序理解：

1. 部、组是组织节点，节点定义数据汇聚和权限所辖范围；父节点覆盖下辖子节点，同级节点保持各自范围。
2. 负责人是人员与组织节点之间的任职关系。一个节点允许多个平级负责人，默认共享节点完整范围，不按人数拆分，也不区分主次；各任职可以单独调整查看范围。
3. 同一稳定 `personId` 可以在不同层级或多个节点存在多条负责人任职。个人数据范围取所有有效任职配置的基础范围与额外组织范围的并集。
4. 本页数据查看范围不等于功能授权。读取须同时满足 HRM 对应读取功能和数据查看范围；编辑、删除、审批的数据范围须另行定义，不得把额外只读范围自动升级为修改范围。
5. 人数和业务指标按节点自身及下级范围汇聚。跨层或多节点负责人按稳定人员 ID 去重；新增一条负责人任职关系本身不改变人员总数。

计算口径：

```text
个人数据范围 = 并集（各有效任职的基础范围 + 额外组织范围）
允许读取 = 身份有效 AND HRM允许对应读取动作 AND 当前系统记录 AND 记录在个人查看范围
写入 / 删除 / 审批 = 另校验动作专属权限和动作专属数据范围，不能直接复用上述读取公式
```

页面只表达 UI 与组织权限模型。生产接入必须由服务端校验稳定人员 ID、组织 ID、当前有效任职、功能权限和数据范围；不得根据前端“负责人”标签直接授予权限。

## 数据约定

- 部门和业务组节点表示数据汇聚与权限所辖范围，不表示一个只能容纳一名负责人的岗位。`managers`、`leaders` 均为数组，同一节点内负责人平级，默认共享该节点完整范围，支持单独配置查看范围。
- 负责人使用稳定 `personId`。同一人可以在部门和业务组等不同层级重复出现，每次出现表示一条独立负责人任职关系；页面标记“跨层任职”。实际权限范围取各有效任职配置的并集，人数汇总按稳定人员 ID 去重。
- 演示部门由田靖、周林共同负责；运营四组由周林、林知夏共同负责。周林在两个层级复用同一 `personId`；林知夏属于本次多人负责人 UI 场景的虚构演示人员，不改变 36 人及组内人数汇总。
- 源稿一个部门、五个业务组、36 人汇总，另有 15 条成员展示节选。36 不等于渲染的成员行数，也不从 15 条节选重算；组长、经理和成员节选不是完整人员库。
- 新增成员增加部门及所在组汇总各 1；调岗保持部门总数，源组减 1、目标组加 1；确认离职减 1。拒绝重复工号、空白必填字段、无效组织、同组调岗、重复组名和重复离职。
- 新业务组的负责人数组为空，显示“待指定负责人”；新增成员无绩效，`kpiRate: null`，显示“待统计”。没有推断入职日期、真实账号或权限。
- 完成率 `>=90` 为优秀，`>=75 && <90` 为良好，`<75` 为预警。空值/无效值不按零绩效展示。
- 本页搜索姓名、工号、组织名和已有登录账号，忽略大小写及空白。登录账号中的字母来自源快照，不推导新人员拼音或首字母；完整拼音选择功能仍使用原有 PersonPicker。
- 编辑、调岗、离职仅作用于节选组员。负责人作为组织范围上下文展示，不提供没有定义的任命流程。
- 所有状态仅保存在当前页面内存，刷新/离开后恢复；页底恢复按钮重置示例数据。没有 localStorage、真实 API、HRM 登录或业务写入。

接入其他系统时，由目标系统提供完整的组织和名册口径、服务端校验与权限、真实数据持久化；不能把演示总数或示例管理员用于业务授权。
